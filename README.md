# 语文小教练

部编版《语文》四年级上册的字词练习。**纯前端、零部署、零成本、离线可用**。

核心流程：**看拼音 → 在田字格里手写 → 交给家长批改 → 按间隔复习。**

---

## 为什么是"手写 + 家长批改"，而不是自动判分

这是被技术现实逼出来的选择，但结果反而更好。

**两件做不到的事：**

1. **网页没法强制调出手机的手写输入法。** `inputmode` 只有 `text / numeric` 等值，**没有 handwriting**——用哪种输入法由系统决定，网页切换不了。
2. **网页自己识别手写代价太大。** 要么内置几十 MB 的识别模型（离线就废了，老机器也扛不住），要么接在线 OCR（要密钥、要联网、有费用，还得把孩子写的字传到别人服务器上）。

这些都和「零成本、纯前端、离线可用」冲突。

**所以改成家长批改。好处是：**

- 孩子**真的在手写**，是"产出"而不是从候选字里挑的"再认"——这正是训练的目的
- 家长看到的是孩子**真实写的那个字**，能看出笔画错、结构歪、少个偏旁。这是自评看不到的，也是识别程序判断不准的
- 批注会跟着这个词存下来，下次复习时重新显示给孩子看

## 流程

### 孩子端

1. 首页**先选单元、再选课时**（第几课 + 课文标题都显示出来，跟课堂进度走）
2. 显示拼音 → 在田字格上用手指写
   - 田字格会自动折行：1~3 个字一行，**4 个字排成 2×2**，5 个字以上每行 3 个
     （四个字并排会窄得没法写）
3. 点「写好了」
   - **不显示答案**。一显示就变成自评了，那还不如直接对答案抄
   - 笔迹（按"点"存）+ 词语 + 时间 → 进"等家长批改"队列

### 家长端（有口令）

首页最下面「家长批改」→ 第一次进来先设 4～6 位数字口令。

- 逐条看：题目（拼音）+ **孩子真实笔迹的回放** + 正确答案
- 点「写对了 / 写错了」，可写批注（如"崩少了山头"）
- 批完 → 出队、进历史、安排下次复习日期
- 「练习报告」也走这道口令：报告里列着错题的正确答案，孩子自己翻到就变成照着抄

**口令的作用**：挡住孩子自己进去点"全对"。它不防外人，所以不加密、不做找回——忘了就清数据重设。
解锁**只在家长端这几页里有效**，一回首页就自动锁上——不然家长批到一半把手机递过去，
孩子接着点就能替自己批改。

### 批改之后：马上给反馈，错的当天订正

**为什么不等到下次复习才告诉他？**
错的字拖几天才纠正，孩子这几天里很可能已经把错的写法记牢了——**错误先入为主，
纠正的成本比当时改高得多**。而且家长那句批注（"崩少了山字头"）当时看才有上下文，
隔几天他早忘了自己当时是怎么写的。

所以：

- 批改完 → 首页立刻出现「家长刚批改了 N 条」，列对错 + 批注 → 点「知道了」清掉
- **写错的字当天就到期**（不是等到明天），下次打开就能订正
- 写对的字才往后推：**第 1 → 2 → 4 → 7 → 15 天**

⚠️ 有个要注意的：看到反馈后**别让孩子立刻照着正确答案再描一遍**（那变成抄）。
先看批注想清楚错在哪，稍后再写。

### 间隔复习（这个模块的重点）

生字最怕的就是"今天会写、下周就忘"，所以**练多少次要，什么时候再练一次才关键**。
出题时**到期的排在最前面**——这是间隔复习真正起作用的地方。四种题型（看拼音写字词、
练组词、多音字选读音、默写）都守这个顺序；以前只有"看拼音写词语"排队，
另外两种整批打乱，到期的字照样排不到前面。

阶梯那一档一档的推进按**日历天**算，不按 24 小时整点。按整点推的话，晚上九点练的字
到第二天晚上八点还没"满 24 小时"，于是这一场整个跳过它，实际隔了两天——
孩子会觉得"这个字我昨天不是练过了吗"。

## 数据

`js/data.js` 由脚本生成，**不要手改**：

- 来源：`01_学习资料库/02_同步资料/四年级上册/语文/单元知识要点与拓展.md`
  里的**写字表 / 词语表 / 多音字 / 易错字**，逐单元摘录到 `data/words.raw.json`
- 拼音由 `pypinyin` 生成后**写死**进 `data.js`，运行时零依赖
- 改内容请改 `data/words.raw.json`，再跑：`npm run gen-data`

默写用的 `js/recite.js`（日积月累 / 古诗三首 / 文言文）**不在生成链路里**，是手工录入、
已逐字对过教材 PDF 的；要改先看文件顶部那份校对记录——默写判的是"和课本一不一样"，
凭印象改一个字，孩子就背错了。

目前：8 单元 / 250 个一类字 / 220 个词 / 265 个二类字（识字表）/ 每单元多音字 + 易错字提示。

### 多音字的读音是怎么定下来的

写字表只有单个字，没有语境。而「降」在《雪梅》"梅雪争春未肯降"里读 **xiáng**，
pypinyin 只会给最常用的 **jiàng** —— 直接生成就是教错的。所以按这个顺序定：

1. `gen_data.py` 里 `LESSON_CHAR_PY` 手工钉死的（附依据，目前 2 条）
2. **同课词语表**里含这个字的词 —— 取词组切分出来的那个音（「哄堂大笑」→ hōng）
3. **同课识字表**的课本注音（课本自己标的，「降」→ xiáng、「塞」→ sài）
4. 都没有才用 pypinyin 的单字默认读音

第 2、3、4 类里凡是改动了默认读音的，都会连依据一起写进
`data/pinyin-review.md` 第三节，家长翻一眼就能核。

### 课本注音的字形映射（以及它坑过的一次）

识字表的拼音在教材 PDF 里是**乱码字形**（ā 存成了 Q），要按 `GLYPH` 表还原。
一个字母只能对应一个带调韵母：曾经 `O` 和 `G` 都写成了 `ǒ`，于是所有 ū 的字
（输 shO、曲 qO、躯 qO、诸 zhO、君 jOn）被标成 shǒ / qǒ / jǒn，
还打着"以教材为准"的名义一路进了数据 —— **孩子天天看着，谁也没发现**。

现在生成时会把解出来的音节拿去核对：韵母必须是普通话那 35 个之一，
`o` 只许跟 b p m f w 拼。解不出合法音节就**退回 pypinyin** 并记进
`data/pinyin-review.md` **第一节**——那一节有内容就说明映射表又错了。
`tests/data.test.js` 里有同样的检查，双向兜底。

### 教案数据：`js/jiaoan.js`

来源：`01_学习资料库/05_课件及辅导资料/（内容版）26秋四上语文教案版本.docx`，
由 `scripts/gen_jiaoan.py` 拆出 8 个单元设计 + 114 篇课时教案 + 19 周教学进度表。

**这份数据只提供三样东西**：教学进度（哪一周讲到第几课）、每课的教学目标 / 重点 /
难点 / 分层作业 / 板书、写字指导里逐字的结构与笔顺。

**它不提供课文原文、古诗、日积月累**。教案是二手整理，默写判的是"和课本一不一样"——
那些内容只能走 `js/recite.js`（对过教材 PDF 的那条链）。

教案自己还带着错：《陀螺》标成 23*、《王戎不取道旁李》标成 22，和课本**正好是反的**；
"方帽子店"前面漏了课次号。所以生成时**课次一律按 `js/data.js` 认，教案只补课次以外的
字段**。`tests/jiaoan.test.js` 里专门钉了这两条。

## 功能

- **练**：看拼音 → 田字格手写 → 交家长批改 → 间隔复习（详见上面"流程"）。
- **练组词（二类字）**：资料页里直接开。给一个字组 2 个词，每词一行、预留 4 格，
  写在田字格里；参考答案只在家长批改时显示，练习时不提示。
- **多音字选读音 / 默写**：这两种由程序当场判分，不用等家长批——它们有唯一正确答案，
  卡在队列里等几天才告诉孩子对错没意义。多音字的选项每轮换一次位置（不然正确的永远排第一个，
  孩子练两题就只点最上面那个）；默写用打字，考的是"记不记得住"，不是"字写得对不对"。
- **资料（只读查阅）**：首页「二类字 / 多音字 / 易错字」一栏，按单元看：
  - 二类字（识字表，只认不写，按课时列出，带拼音）
  - 多音字（每个字列出不同读音和课文里的例子）
  - 易错字提醒（部首、笔画、形近字辨析）
  - 写字要点（教案里逐字的结构、笔顺、易错笔画，比"易错字"那几条具体得多）
  - 本课重点 / 单元要点（教案的教学目标、重难点、分层作业、板书）
- **本周课堂**：首页按教案的教学进度表算出这周学校讲到第几课，点一下就把练习范围
  切到那一课 —— 练的字跟课堂对得上，不用家长自己翻课程表。假期里显示开学第一周。

## 跨设备同步（可选，默认关）

- **默认**：数据只在这台设备上，一个字节都不上传 —— 和以前一样。
- **家长端不是一个单独的网址**：就是同一个网址，首页最下面「家长批改 / 练习报告」进去（要口令）。
  口令各台设备各设一次（它只存在那台设备上）。
- **语文和数学共用一个家庭码**（一个码管两个项目，家长只要记一个）。
  两边的数据在服务端是分开存的，不会串：语文报告里不会出现数学那台设备的统计，
  数学清空数据也不会把语文的作业带走。
- **开了之后**（家长报告页 →「跨设备同步」→ 生成一个家庭码，另一台设备填同一个码）：
  - 孩子在平板写 → 笔迹自动上传 → **家长在自己手机上批改** → 结果自动回到平板
  - 家长报告里能看到别的设备练得怎么样 —— **在自己手机上看报告也不是空的**：
    报告会把本机和各台设备上传的记录合在一起显示
- **不用点同步**：
  - 孩子那边：**一整轮写完才上传一次**（不是写一个传一个）
  - 家长这边：**这一批改完才上传一次**（字词拼音批得快，一条一传纯属浪费）
    —— 批到一半离开、或者切到后台，也会把攒下的传走；批完直接关页面也不丢
  - 打开页面时取一次结果。关掉页面就完全不联网
  （一天大约十来次请求，不做定时轮询，不耗电不跑流量）。
- **云端只存在途数据**：作业批完就删、批改结果取走就删、统计只留每台设备最新一份。
  全量历史一直在孩子这台设备上（`history` 2000 条、`stats` 全量）。
- **家庭码是唯一一道门**：知道码的人能看报告、能批改。别发给外人。
  格式是 `xxxx-xxxx-xxxx`（12 位，字母数字，中间两道横杠）。**只有第一台设备生成码，
  别的设备一律填这个码** —— 各生成各的等于两个互不相通的家庭（界面都显示"已开启"，
  但永远看不到对方的作业）。换码也一样，会让已填旧码的设备全部失联。
- **最后一位是校验位**：抄错一位当场就会提示"这个码抄错了"，不会让你静默连进一个空家庭。
- 传不上去的时候，报告页那句状态会写成「有作业没传上去，切到后台再回来就会重试」——
  刻意不做定时重试（不耗电、不跑流量），所以要给人一条自己能动手的路。
- 后端是 `10_家庭数据同步`（GitHub 私有仓库存主、CloudBase 云函数代理）。

批改仍然是"家长看孩子真实笔迹"这一套 —— 跨设备只是把笔迹送到家长眼前，
判分还是人来做。

### 两个家长都要批改

- 两台手机都打开**同一个网址**，都填上**同一个家庭码**，各设一次自己的口令
  （口令只存在各自设备上，所以换设备就要再设一次）。
- 批改队列是云端同一份：**谁先批谁生效，同一条只认一次**。
  另一个人批到同一条时，会看到一句「这条已经被另一台设备批过了」，队列自动刷新成最新的。
- 两边批的结果都会回到孩子那台设备，复习排期只在那台设备上算一次（不会算两遍）。

## 已知限制

- **不开同步时，批改要在同一台设备上**：孩子用平板写，家长拿同一台平板批。
  开了跨设备同步就没有这个限制（见上一节）。
- **没批改的题不计入统计**：不然"做了但没批"会把数据搅浑。首页会显示"有 N 条等家长批改"，不会漏。
- **笔迹按"点"存，换设备/清数据就没了**。
- **没有"错题重做本"**：错过的字靠到期排队自己回到下一场里，孩子端看不到一个专门的错题列表（报告在家长端）。
- **判分不识别手写**：手写题一律等家长批。这是开头那两条技术现实决定的，不是偷懒。

## 下一步

1. **形近字 / 同音字辨析**（如"既/即""曰/日"，资料里的易错字就是素材）
2. **听写模式**：家长念、孩子写（或反过来）。现在只有"看拼音写"，缺"听音写"这一半，
   而课堂上的听写才是考法
3. 家长报告再往前一步：按课时看"哪一课的字还没过"，跟课堂进度对齐

### v0.4.0

- **跨设备同步（可选，默认关）**：家长报告页里生成/填写家庭码即可。
  孩子在 A 设备写完 → 家长在 B 设备批改（看到真实笔迹）→ 结果自动回到 A 设备。
  不用点同步按钮：写完、批完、打开页面时自动联网，平时完全不联网。
  云端只存在途数据（批完即删、取走即删、统计覆盖写），全量历史仍在本机。
- **笔迹改成按格子存**（`cell` + 格内相对位置 u/v），不再存画布像素。
  这是跨设备回放的前提：平板 700px 宽、手机 360px 宽，像素坐标画出来会偏出格子，
  家长看到的就不是孩子写的那个字了。旧格式的历史笔迹照原样回放。
- **批改队列可以包含别的设备上传的作业**，页头标出"这一条是「平板」上写的"；
  在别的设备上写的字，复习排期在那台设备上算，本机不重复记。
- **批改统一走一条路**：本机批和跨设备批都生成同一份批改结果，规则不会分叉；
  同一条只认一次（先到为准），避免掌握度被算两遍。
- **上传时机按"整轮"走**：孩子写完一整轮才上传一次（不是写一个传一个）；
  中途退出会把已写的那几条传上去；上次没传成功的，下次开机补。
- **批改结果也是攒一批传一次**：批完这一批（或离开批改页、切到后台）才发；
  攒下的记在本机，批完直接关页面也不丢。两个家长同时批到同一条时，先到的为准，
  另一个会看到「这条已经在别处批过」。

  现在生成时会核对解出来的音节是不是普通话里存在的（`tests/data.test.js` 里同样查一遍），
  不合法就退回 pypinyin 并记进 `data/pinyin-review.md` 第一节。
  详见上面「课本注音的字形映射」。
- **多音字的读音改成按课文语境定**，不再拿 pypinyin 的单字默认值猜：
  同课词语 → 同课识字表注音 → 手工钉死（附依据）→ 才用默认。见「多音字的读音是怎么定下来的」。
- **间隔复习真的生效了**：`level` 以前被直接当阶梯下标用，第一档（1 天）永远轮不上，
  第一档实际是 2 天；最高档也够不到 15 天。同时"到期优先"以前只管看拼音写字词，
  组词和多音字整批打乱 —— 到期的排不到前面，复习等于没做。现在四种题型一套顺序，
  到期时间按日历天算。`tests/srs.test.js` 守住这几条。
- **作答链路的四处修正**：
  - 练习模式（看拼音 / 看词语）以前没进存储白名单，重开页面就跳回默认，孩子又练一遍已经会的
  - 自动判分给的那句正确答案以前被写进 `note` 字段，报告里就成了"家长说：这一句是……"
  - 「练习报告」以前孩子可以直接翻，里面列着错题答案 —— 现在和批改页同一道口令；
    家长端的解锁也只在家长端这几页有效，回首页自动锁上
  - 待批改的题在**写的那一刻**就钉上单元：批改往往是几天以后，那时家长可能已经切了单元，
    统计会串到别的单元去
- **两根手指同时落在田字格上不再并成一笔**（每根手指各记各的），多音字选项每轮换位置。
- **转屏之后重量一次画布**，并且绑事件只做一次：以前每次刷新都往同一个画布上再绑一套
  指针事件，一次落笔会被记成两笔，家长批的就不是孩子写的那个字。
- 本地存储读坏 / 存不进去都会说出来（`store.js` 加类型校验，界面顶部给一句提示），
  不再静默回到空白状态。测试 27 → 46。
