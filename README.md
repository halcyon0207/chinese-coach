# 语文小教练

部编版《语文》四年级上册的字词练习。**纯前端、零部署、零成本、离线可用**。

核心流程：**看拼音 → 在田字格里手写 → 交给家长批改 → 按间隔复习。**

---

## 为什么是"手写 + 家长批改"，而不是自动判分

这是被技术现实逼出来的选择，但结果反而更好。

**两件做不到的事：**

1. **网页没法强制调出手机的手写输入法。** `inputmode` 只有 `text / numeric` 等值，**没有 handwriting**——用哪种输入法由系统决定，网页切换不了。
2. **网页自己识别手写代价太大。** 要么内置几十 MB 的识别模型（离线就废了，老机器也扛不住），要么接在线 OCR（要密钥、要联网、有费用，还得把孩子写的字传到别人服务器上）。

这些都和「零成本、纯前端、离线可用」冲突。

**所以改成家长批改。好处是：**

- 孩子**真的在手写**，是"产出"而不是从候选字里挑的"再认"——这正是训练的目的
- 家长看到的是孩子**真实写的那个字**，能看出笔画错、结构歪、少个偏旁。这是自评看不到的，也是识别程序判断不准的
- 批注会跟着这个词存下来，下次复习时重新显示给孩子看

## 流程

### 孩子端

1. 首页**先选单元、再选课时**（第几课 + 课文标题都显示出来，跟课堂进度走）
2. 显示拼音 → 在田字格上写
   - 田字格**竖着排一列、靠右摆**，画布只占格子那一块，左边留出空白给手掌：
     铺满整行的话，写字时压在屏上的手掌也会被当成笔迹画上去
   - 字多时格子按屏幕高度收一点，尽量一屏写完（不用在画布上滑屏 ——
     画布上是 `touch-action:none`，不然写字会被滚动打断）
   - 组词题仍是一词一行、每行固定 4 格
3. 点「写好了」
   - **不显示答案**。一显示就变成自评了，那还不如直接对答案抄
   - 笔迹（按"点"存）+ 词语 + 时间 → 进"等家长批改"队列
4. **上传是纯手动的**：什么时候传、什么时候批，由人自己挑时间 —— 点一下练习页上的
   「提交给家长批改」就把**已经写好的全部**一起传上去（不是写一条传一条）。
   不点它不会自己传：整轮写完不传、中途退出不传、切到后台也不传，作业一直留在这台设备上
   （家长在同一台设备上照样能批）
5. 练习页还有「查看批改」：家长批过的对错、批注、日期都在这儿，随时能翻回去看
   （首页「资料」栏里也有同一个入口）
6. 中途被打断（关页面、平板没电、被叫走）也不怕：下次进同一台设备，首页会出现
   「上次还没写完」，点「继续写」接着上次的位置 —— 已经写过的不再出现，也不会重算

### 家长端（有口令）

首页最下面「家长批改」→ 第一次进来先设 4～6 位数字口令。

- 逐条看：题目（拼音）+ **孩子真实笔迹的回放** + 正确答案
- 点「写对了 / 写错了」，可写批注（如"崩少了山头"）
- 批完 → 出队、进历史、安排下次复习日期
- **「提交批改」**可以把已经批好的马上传回孩子那台设备（队列批完本来也会自动传，
  这个按钮给的是"我现在就要让他看到"那条路）
- **想找新作业就点一下**：「看看有没有新交上来的作业」按钮 —— 孩子刚交的会立刻出现，
  没有新的也会说一句"没有新交上来的作业"。**不做自动轮询**：联网只发生在打开页面、
  从后台切回、以及点这个按钮的时候（见下面"跨设备同步"一节）
- 批改历史里**字词和拼音一起显示**：这样才分得清这一条批的是「看拼音写词语」
  还是「看词语写拼音」（写拼音那一档只看汉字是看不出来的）
- 「练习报告」也走这道口令：报告里列着错题的正确答案，孩子自己翻到就变成照着抄
  - 报告里把**批改的全部内容**摆出来：批成对/错的每一条、家长的批注、批改日期，
    另有按题型 / 按单元 / 错题三块统计
  - **能按时间段看**：今天 / 最近 7 天 / 最近 30 天 / 全部（默认最近 7 天）——
    家长问的通常是"这几天他练得怎么样"，不是"有史以来"。切换只筛「批改记录」和
    「错题」两块明细；总览、按题型、按单元一直是累计（那些数字变小反而像数据丢了）
  - 页顶有「刷新」按钮：点一下拉一次别的设备的最新统计（打开报告页时也会自动拉一次）
  - 报告页只放报告：「跨设备同步」的设置收在它自己那一页（页顶有一个入口）

**口令的作用**：挡住孩子自己进去点"全对"。它不防外人，所以不加密、不做找回——忘了就清数据重设。
解锁**只在家长端这几页里有效**，一回首页就自动锁上——不然家长批到一半把手机递过去，
孩子接着点就能替自己批改。

### 批改之后：马上给反馈，错的当天订正

**为什么不等到下次复习才告诉他？**
错的字拖几天才纠正，孩子这几天里很可能已经把错的写法记牢了——**错误先入为主，
纠正的成本比当时改高得多**。而且家长那句批注（"崩少了山字头"）当时看才有上下文，
隔几天他早忘了自己当时是怎么写的。

所以：

- 批改完 → 首页立刻出现「家长刚批改了 N 条」，列对错 + 批注 → 点「知道了」清掉
- **写错的字当天就到期**（不是等到明天），下次打开就能订正
- 写对的字才往后推：**第 1 → 2 → 4 → 7 → 15 天**

⚠️ 有个要注意的：看到反馈后**别让孩子立刻照着正确答案再描一遍**（那变成抄）。
先看批注想清楚错在哪，稍后再写。

### 间隔复习（这个模块的重点）

生字最怕的就是"今天会写、下周就忘"，所以**练多少次要，什么时候再练一次才关键**。
出题时**到期的排在最前面**——这是间隔复习真正起作用的地方。四种题型（看拼音写字词、
练组词、多音字选读音、默写）都守这个顺序；以前只有"看拼音写词语"排队，
另外两种整批打乱，到期的字照样排不到前面。

阶梯那一档一档的推进按**日历天**算，不按 24 小时整点。按整点推的话，晚上九点练的字
到第二天晚上八点还没"满 24 小时"，于是这一场整个跳过它，实际隔了两天——
孩子会觉得"这个字我昨天不是练过了吗"。

**到期的会摆在首页**：以前"到期"只体现在排队顺序里 —— 引擎自己知道，孩子看不见；
报告页那句"今天到期该复习 N 个"又在口令后面，只有家长看得到。现在首页有一张
「今天该复习（N）」：列出到期的字词，还有一个「就练这些」按钮，点一下直接开一轮
**只含到期项的练习，不掺新字**（跨单元的到期一起收；同一个字在两课里都出现时只算一条，
复习排期本来就是按"字词"记的，不是按课记的）。

**一轮里练什么不是随机的**：正式练习是"选定课（或单元）后把那一课的字词**全部排上**"，
不抽题 —— 免得一课的常用词被随机漏掉。系统决定的是**顺序**（到期的排最前面、
没练过的其次）和**什么时候该再来一次**。所以第二次练同一课时，看到的还是那批字，
只是到期的会先出来 —— 这是刻意的。

## 数据

`js/data.js` 由脚本生成，**不要手改**：

- 来源：`01_学习资料库/02_同步资料/四年级上册/语文/单元知识要点与拓展.md`
  里的**写字表 / 词语表 / 多音字 / 易错字**，逐单元摘录到 `data/words.raw.json`
- 拼音由 `pypinyin` 生成后**写死**进 `data.js`，运行时零依赖
- 改内容请改 `data/words.raw.json`，再跑：`npm run gen-data`

默写用的 `js/recite.js`（日积月累 / 古诗三首 / 文言文）**不在生成链路里**，是手工录入、
已逐字对过教材 PDF 的；要改先看文件顶部那份校对记录——默写判的是"和课本一不一样"，
凭印象改一个字，孩子就背错了。

目前：8 单元 / 250 个一类字 / 220 个词 / 265 个二类字（识字表）/ 每单元多音字 + 易错字提示。

### 多音字的读音是怎么定下来的

写字表只有单个字，没有语境。而「降」在《雪梅》"梅雪争春未肯降"里读 **xiáng**，
pypinyin 只会给最常用的 **jiàng** —— 直接生成就是教错的。所以按这个顺序定：

1. `gen_data.py` 里 `LESSON_CHAR_PY` 手工钉死的（附依据，目前 2 条）
2. **同课词语表**里含这个字的词 —— 取词组切分出来的那个音（「哄堂大笑」→ hōng）
3. **同课识字表**的课本注音（课本自己标的，「降」→ xiáng、「塞」→ sài）
4. 都没有才用 pypinyin 的单字默认读音

第 2、3、4 类里凡是改动了默认读音的，都会连依据一起写进
`data/pinyin-review.md` 第三节，家长翻一眼就能核。

### 课本注音的字形映射（以及它坑过的一次）

识字表的拼音在教材 PDF 里是**乱码字形**（ā 存成了 Q），要按 `GLYPH` 表还原。
一个字母只能对应一个带调韵母：曾经 `O` 和 `G` 都写成了 `ǒ`，于是所有 ū 的字
（输 shO、曲 qO、躯 qO、诸 zhO、君 jOn）被标成 shǒ / qǒ / jǒn，
还打着"以教材为准"的名义一路进了数据 —— **孩子天天看着，谁也没发现**。

现在生成时会把解出来的音节拿去核对：韵母必须是普通话那 35 个之一，
`o` 只许跟 b p m f w 拼。解不出合法音节就**退回 pypinyin** 并记进
`data/pinyin-review.md` **第一节**——那一节有内容就说明映射表又错了。
`tests/data.test.js` 里有同样的检查，双向兜底。

### 教案数据：`js/jiaoan.js`

来源：`01_学习资料库/05_课件及辅导资料/（内容版）26秋四上语文教案版本.docx`，
由 `scripts/gen_jiaoan.py` 拆出 8 个单元设计 + 114 篇课时教案 + 19 周教学进度表。

**这份数据只提供三样东西**：教学进度（哪一周讲到第几课）、每课的教学目标 / 重点 /
难点 / 分层作业 / 板书、写字指导里逐字的结构与笔顺。

**它不提供课文原文、古诗、日积月累**。教案是二手整理，默写判的是"和课本一不一样"——
那些内容只能走 `js/recite.js`（对过教材 PDF 的那条链）。

教案自己还带着错：《陀螺》标成 23*、《王戎不取道旁李》标成 22，和课本**正好是反的**；
"方帽子店"前面漏了课次号。所以生成时**课次一律按 `js/data.js` 认，教案只补课次以外的
字段**。`tests/jiaoan.test.js` 里专门钉了这两条。

## 开发

```bash
npm test             # 149 个测试（界面冒烟 + 字词数据体检 + 教案体检 + 间隔复习 + 跨设备同步）
npm run gen-data     # 重新生成带拼音的字词数据（需要 python + pypinyin）
npm run gen-jiaoan   # 重新生成教案数据（需要 python，纯标准库）
```

也可以直接双击 `index.html`（用的是普通 script，不是 ES module）。

## 功能

- **今天要做的（首页清单）**：订正 → 复习 → 今天还没练的那几类，每行一个按钮；
  做过的标"✓ 今天做过"。哪件事先做、还差哪件，一眼看完。
- **练**：看拼音 → 田字格手写 → 交家长批改 → 间隔复习（详见上面"流程"）。
- **提交给家长批改（手动上传）**：练习页上点一下就传 —— 写好的全部一起交，**不点不传**
  （整轮写完、中途退出、切到后台都不会自己传，时间自己掌控）。
- **查看批改**：孩子也能看家长批了什么 —— 对错、批注、日期，首页和练习页都有入口。
- **接着上次写**：练习被打断不会白写，下次进同一台设备接着上次的位置。
- **哪天练过**：课时按钮上标着这一课最后一次练的日期；练习页写着这个字词上次什么时候练的。
- **练组词（二类字）**：资料页里直接开。给一个字组 2 个词，每词一行、预留 4 格，
  写在田字格里；参考答案只在家长批改时显示，练习时不提示。
- **多音字选读音 / 默写**：这两种由程序当场判分，不用等家长批——它们有唯一正确答案，
  卡在队列里等几天才告诉孩子对错没意义。多音字的选项每轮换一次位置（不然正确的永远排第一个，
  孩子练两题就只点最上面那个）；默写用打字，考的是"记不记得住"，不是"字写得对不对"。
- **资料（只读查阅）**：首页「二类字 / 多音字 / 易错字」一栏，按单元看：
  - 二类字（识字表，只认不写，按课时列出，带拼音）
  - 多音字（每个字列出不同读音和课文里的例子）
  - 易错字提醒（部首、笔画、形近字辨析）
  - 写字要点（教案里逐字的结构、笔顺、易错笔画，比"易错字"那几条具体得多）
  - 本课重点 / 单元要点（教案的教学目标、重难点、分层作业、板书）
- **本周课堂**：首页按教案的教学进度表算出这周学校讲到第几课，点一下就把练习范围
  切到那一课 —— 练的字跟课堂对得上，不用家长自己翻课程表。假期里显示开学第一周。

## 跨设备同步（可选，默认关）

- **默认**：数据只在这台设备上，一个字节都不上传 —— 和以前一样。
- **家长端不是一个单独的网址**：就是同一个网址，首页最下面
  「家长批改 / 练习报告 / 跨设备同步」进去（都要口令）。
  口令各台设备各设一次（它只存在那台设备上）。
- **语文和数学共用一个家庭码**（一个码管两个项目，家长只要记一个）。
  两边的数据在服务端是分开存的，不会串：语文报告里不会出现数学那台设备的统计，
  数学清空数据也不会把语文的作业带走。
- **开了之后**（首页「跨设备同步」→ 这台是第一个就生成一个家庭码，另一台填同一个码）：
  - 孩子在平板写 → 笔迹自动上传 → **家长在自己手机上批改** → 结果自动回到平板
  - 家长报告里能看到别的设备练得怎么样 —— **在自己手机上看报告也不是空的**：
    报告会把本机和各台设备上传的记录合在一起显示
- **默认不用点同步，想点也有按钮**：
  - 孩子那边：**只有点「提交给家长批改」才会传**（写好的全部一起传，不是写一条传一条）。
    不点就一直留在本机 —— 练完了、或者练到一半，挑个时间点一下就行；
    交完会明确说"已提交 N 条"还是"没传上去"
  - 家长这边：**这一批改完才上传一次**（字词拼音批得快，一条一传纯属浪费），
    也可以点「提交批改」马上传；批到一半离开、或者切到后台，也会把攒下的传走；
    批完直接关页面也不丢
  - 联网只发生在几个明确的时刻：打开页面、从后台切回来，以及点「提交给家长批改 /
    提交批改 / 看看有没有新作业 / 刷新」。**上传 100% 手动**（作业不点不传），
    也**不做定时轮询** —— 想看有没有新东西，点一下那个按钮就行
  （一天下来还是十来次请求，不耗电不跑流量）。
- **云端只存在途数据**：作业批完就删、批改结果取走就删、统计只留每台设备最新一份。
  全量历史一直在孩子这台设备上（`history` 2000 条、`stats` 全量）。
- **家庭码是唯一一道门**：知道码的人能看报告、能批改。别发给外人。
  格式是 `xxxx-xxxx-xxxx`（12 位，字母数字，中间两道横杠）。**只有第一台设备生成码，
  别的设备一律填这个码** —— 各生成各的等于两个互不相通的家庭（界面都显示"已开启"，
  但永远看不到对方的作业）。换码也一样，会让已填旧码的设备全部失联。
- **最后一位是校验位**：抄错一位当场就会提示"这个码抄错了"，不会让你静默连进一个空家庭。
- 传不上去的时候，报告页那句状态会写成「有作业没传上去，再点一次『提交给家长批改』
  就会重试」—— 刻意不做定时重试（不耗电、不跑流量），所以要给人一条自己能动手的路。
- 后端是 `10_家庭数据同步`（GitHub 私有仓库存主、CloudBase 云函数代理）。

批改仍然是"家长看孩子真实笔迹"这一套 —— 跨设备只是把笔迹送到家长眼前，
判分还是人来做。

### 两个家长都要批改

- 两台手机都打开**同一个网址**，都填上**同一个家庭码**，各设一次自己的口令
  （口令只存在各自设备上，所以换设备就要再设一次）。
- 批改队列是云端同一份：**谁先批谁生效，同一条只认一次**。
  另一个人批到同一条时，会看到一句「这条已经被另一台设备批过了」，队列自动刷新成最新的。
- 两边批的结果都会回到孩子那台设备，复习排期只在那台设备上算一次（不会算两遍）。

## 已知限制

- **不开同步时，批改要在同一台设备上**：孩子用平板写，家长拿同一台平板批。
  开了跨设备同步就没有这个限制（见上一节）。
- **跨设备批改要点一下"提交"**：作业不会自己飞过去。孩子写完（或者练到一半）点一次
  「提交给家长批改」，家长那边才看得到；不点的话作业一直只在这台设备上。
- **没批改的题不计入统计**：不然"做了但没批"会把数据搅浑。首页会显示"有 N 条等家长批改"，不会漏。
- **笔迹按"点"存，换设备/清数据就没了**。
- **没有"错题重做本"**：错过的字靠到期排队自己回到下一场里，孩子端看不到一个专门的错题列表（报告在家长端）。
- **判分不识别手写**：手写题一律等家长批。这是开头那两条技术现实决定的，不是偷懒。

"作业一直传不上去（Failed to fetch）"——查了两天，结论是**数据太大**，而作者一开始

|---|---|

| ③ 页面里发的 120 KB 请求 | **失败（连不上）** |

同一台设备、同一个页面：小请求 253 毫秒就回来，120 KB 直接被掐断。

所以是"一趟背得太多"。

- **`BATCH_MAX_BYTES` 150KB → 40KB**：原来按"能装多少装多少"切，起点就顶在

  还过不去再拆，最差拆到一条（十 KB 上下）。代价是多跑几趟，但一定传得完。

- **「测一下网络」变三步**：先直连、再小请求、再按真实体量（120KB）走一趟。

- **练习页显示"待家长批改 43 条 · 约 539 KB"**：这个数以前谁都看不见，

### v0.8.1

家长报的：**"昨天平板做完提交了，手机端一直收不到。"** 查下来是三件事，
两件会让"看着提交了、其实没传"，一件会让它**再也不补传**。

- **"还有没传的"没有落盘（最要紧的一条）**：`sync.dirty` 只改内存不写本机。
  提交传到一半被关掉（或页面被刷新、网络抖一下），下次打开 `dirty` 又变回 false ——
  那批作业就**再也不会自动补传**，除非有人想起来再点一次「提交给家长批改」。
  现在标脏、传完、失败这三个时刻都会立刻落盘（`hooks.onSave` → `saveState`）。
- **自动刷新版会把提交打断**：昨天加的"打开时检查新版本"，如果点完提交之后
  那条 fetch 才回来，页面就被 `location.replace` 冲掉一次 —— 孩子这边看着像提交了，
  家长那头一条都没有，而且页面上没有任何错误。现在**只要他点过/写过/提交过
  就不再重载**，等下次打开再换新版本。
- **"这次一条都没传"时界面在骗人**：`flushWork` 没有新作业时会返回 `ok:true` 加
  `skipped`，界面照旧说"已提交 N 条"。现在照实说"这次没有要新传的作业"，
  并指出下一步：让家长在手机上点一下「看看有没有新作业」。
- **请求超时没有兜住（很可能是"一直在提交"的直接原因）**：原来只靠
  `AbortController` 掐掉请求 —— 不支持它的旧浏览器上**根本没有超时**，
  fetch 一直挂着，这个 Promise 永远不返回，界面就永远停在"正在提交…"，
  家长那头自然一直收不到。现在用 `Promise.race` 自己兜一层：到点一定给调用方
  一个结果。**超时也不再重试**（原来会再等一轮，25+25 秒界面一直挂着），
  立刻失败反而好 —— 界面马上说"没提交上去（超时）"，而断点续传的账已经在本机，
  再点一次只补没传完的。
- **明确没网时不发请求**：`navigator.onLine === false` 时直接返回失败（不发），
  省掉一次 25 秒的干等。反过来不成立（连上 WiFi 也可能没互联网），那种照发。
- **提交传到一半时按钮变灰**：原来再点一次会被 `flushWork` 挡住（dirty 已清），
  界面上却毫无变化，孩子只会以为坏了然后一直点。现在按钮换成「正在提交…」并禁用。
- 手动点「看看有没有新作业」时，如果家长**正在写批注就不重绘** ——
  批注的文字其实不会丢（每次输入都同步进 `app.note`），但重绘会把焦点从输入框
  上拿走，正打着字被打断很烦。
- 批改发出前后都落盘（`flushGrades` 的 outbox），和作业流保持一致。
- 同步状态改成说「**已发出** · X 分钟前」：原来写"已同步"会让人以为对方已经收到，
  而这里记录的只是本机最后一次把请求**发出去**的时间。
- 顺手修一处我自己的错：数学 `index.html` 里自检脚本的 `CUR` 和 meta 的
  `app-ver` 没跟着版本号一起改（停在 `b`），于是每次打开都会白白重载一次 ——
  正好赶上提交就被打断。两个项目都补了一条测试把"版本号三处一致"钉住。
- 测试 106 → **110**（脏标记落盘、超时兜底、离线门控、版本号一致各 1 条）。

### v0.7.5

又是拿笔在平板上用了一天之后的反馈：**组词的格子太小，笔画还是偶尔断一截。**

- **组词的田字格大了一圈**（72px → 150px）。根子不在"格子设小了"，而在排格子的算法：
  组词是 4 格一行、一共 2 行，却被按"8 格一列"去分屏幕高度 —— 一屏切 8 份，
  每份只剩 72px。现在高度预算按**行数**算，组词 2 行就吃满可用宽度，
  真是一列 8 格的竖排（练习页）照旧收着。
- **手写笔的断笔收窄了一截**：
  - 接上 `pointerrawupdate`。浏览器帧率一掉，`pointermove` 就只剩每帧一个点，
    笔画跟着一截一截断；这个事件会把笔的原始采样立刻送过来（笔常是 120Hz 以上）。
    不支持的浏览器（iOS Safari、老版本）根本不派发它，走原来的 `pointermove`，
    不用改任何东西。
  - 两条路可能拿到同一批采样点，按坐标判重：同一段不会画两遍，笔迹数组也不会
    凭空胀一倍（那点重叠会顺着上传队列一路带到云端去）。
  - `pointercancel`（掌拒、系统手势打断）之后的续笔宽限 150ms → 300ms。
    被动式电容笔笔尖稍微翘一点，浏览器就先来一个 cancel，孩子抬都不抬接着写 ——
    150ms 那种"很短"的宽限常常赶不上，笔迹就在那儿断一截。真写完抬手走的是
    `pointerup`，不受这条影响，不会把两个字连起来。
  - 顺带补一处：cancel 的那一刻立刻记下"笔刚断过"。不然续笔宽限那 0.3 秒里
    手掌压上来，会被当成手指起一笔，字上多一道掌痕。
